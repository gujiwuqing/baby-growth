# baby-growth 项目问题与优化清单

> 评审时间：2026-06-05
> 评审范围：全项目（5647 行代码，含 utils 工具层、pages 页面层、record 记录页、工程配置）
> 技术栈：uni-app + Vue 3 (`<script setup>`) + TypeScript
> 架构特点：数据层双环境 —— APP 端走 `plus.sqlite`，H5 端用 localStorage + 正则解析 SQL 模拟

---

## 一、问题概览

| 严重等级 | 数量 | 说明 |
| --- | --- | --- |
| 🔴 高危 | 8 | 导致崩溃、数据错误、安全风险，需优先修复 |
| 🟠 中危 | 12 | 影响功能正确性或可维护性 |
| 🟡 低危 | 10+ | 代码风格、体验打磨、潜在隐患 |

**两个根因级问题**（修复它们能连带消除大量衍生问题）：
1. **数据层全程字符串拼接 SQL、无参数化** → 引发 SQL 注入 + 单引号写库失败。
2. **H5 正则解析器能力残缺 + 记录表未建表** → 引发跨端行为不一致、APP 真机写入失败。

---

## 二、🔴 高危问题（必须优先修复）

### H1. 记录表从未建表，APP 真机端写入必然失败
- **位置**：`utils/database.ts` 的 `initTables()`（L435 起）只有 `CREATE TABLE IF NOT EXISTS vaccines`（L440）。
- **问题**：`feeds / diapers / sleeps / foods / supplements / growth_records / baby_info / photos / reminders` 共 9 张表**全项目没有任何 CREATE 语句**。APP 端首次写入这些表会直接因"no such table"报错。H5 端因 localStorage 用对象自动建表而侥幸能跑——**这正是为何此前所有 bug 都只在 H5 环境暴露**。
- **修复**：在 `initTables` 的 `#ifdef APP-PLUS` 分支补齐全部表的建表语句（字段对齐 `getTableColumns` 中的 schema 定义）。

### H2. SQL 全程字符串拼接，存在注入与写库失败风险
- **位置**：`utils/database.ts` `executeSql` 直接把拼好的字符串交给 `plus.sqlite.executeSql`，无参数绑定。
- **问题**：所有写库点用模板字符串拼用户输入。仅 `feeding.vue`（L223 `note.replace(/'/g, "''")`）做了单引号转义，其余 **5 个记录页全裸拼**：
  - `record/diaper.vue` note、`record/sleep.vue` note、`record/growth.vue` note、`record/food.vue` note+foodType、`record/supplement.vue` note+dosage
  - `settings/index.vue`（L51-66）宝宝姓名 `name = '${...}'` 裸拼
- **后果**：用户姓名或备注里输入一个英文单引号（如 `D'Angelo`），APP 端 `executeSql` 直接 reject → 保存失败；恶意构造可篡改其他字段。
- **修复**：数据层提供参数化接口 `executeSql(sql, params[])`（`plus.sqlite` 支持 `?` 占位符），或至少统一 `escape()` 做 `'` → `''` 转义，所有页面改用统一封装。

### H3. H5 模拟解析器能力残缺，跨端统计/排序系统性错误
- **位置**：`utils/database.ts` `selectLocalSql`（约 L340-410）、`executeLocalSql`（约 L150-310）。
- **问题**：手写正则只支持 `=`、`>=`、`COUNT(*)`、单层 `GROUP BY`、`LIMIT`，**不支持** `ORDER BY`、`SUM/AVG`、`<`/`<=`、`OR`、`LIKE`、`!=`、`IN`、`BETWEEN`。导致 H5 下：
  - 首页/喂养页 `SUM(amount)` 恒为 undefined，统计错误（`index/index.vue` L102、`feeding/index.vue` L172）
  - `ORDER BY timestamp DESC LIMIT 1` 取"最新"实为插入顺序首条（`growth/index.vue` L171）
  - "今日/本周"区间查询只过滤起始边界、丢失 `< end` 结束边界，跨天数据被算进今日
- **修复**：补齐 H5 解析器对 `ORDER BY`/聚合/范围操作符的支持；或引入 sql.js / 封装语义化内存 CRUD 替代正则解析。

### H4. INSERT 自增 id 用「数组长度 + 1」，删除后会主键冲突
- **位置**：`utils/database.ts` H5 INSERT 分支（约 L169）`{ id: this.data[table].length + 1 }`。
- **问题**：删除中间行后 length 减小，新插入 id 与现存 id 重复，破坏 `:key` 唯一性与 UPDATE/DELETE 定位。与 SQLite AUTOINCREMENT「永不复用」行为不一致。
- **修复**：维护持久化的单调递增计数器，或用 `Math.max(...ids) + 1`。

### H5. 多个记录页「选了时间却不入库」
- **位置**：`record/diaper.vue`、`record/food.vue`（L67）、`record/supplement.vue`（L57）、`record/growth.vue`（L89）。
- **问题**：模板提供了时间/日期选择器，但保存时 `timestamp` 直接存 `Date.now()`，用户选的时间被**静默丢弃**，入库永远是"点保存的那一刻"。这是隐蔽且影响数据正确性的功能 bug。
- **修复**：保存前把 picker 选中的日期/时间转成时间戳入库。

### H6. settings 不保存 gender，导致成长曲线男宝百分位全错
- **位置**：`settings/index.vue` `saveBabyInfo`（L48-58）只存 name/birthday，未写 gender；`growth/index.vue`（L297）按 `gender === 1 ? 'male' : 'female'` 取值。
- **问题**：gender 恒为 undefined → 永远按 female 计算 WHO 百分位，男宝数据全部偏差。
- **修复**：设置页增加性别选择项并入库；生日/性别变更后重算相关数据。

### H7. clearAllData 漏删 vaccines 与 baby_info
- **位置**：`settings/index.vue` `clearAllData`（L150-170）的 DELETE 表列表仅 7 张，缺 `vaccines`、`baby_info`。
- **问题**："清空所有数据"名不副实，疫苗记录和宝宝信息残留。
- **修复**：补全所有表，或遍历表名统一清空，并重置当前页面 ref。

### H8. growth.vue 数值字段无类型约束，脏数据裸拼进 SQL
- **位置**：`record/growth.vue` 模板身高/体重/头围 input 缺 `type`（L24/L33/L42），保存 `${formData.value.height || 'NULL'}`（L94-95）。
- **问题**：可输入"约50"等任意文本，被裸拼进 SQL 数值位 → 语法错误或脏数据。
- **修复**：input 加 `type="digit"`，保存前 `Number()` 校验 + 合理范围限制（如身高 0-150cm）。

## 三、🟠 中危问题

### 数据层 / 工具层

- **M1. DELETE 多条件 AND 语义写反**（`database.ts` 约 L300）：filter 里「任一条件命中即删除」，与 SQL「全部命中才删」语义相反，多条件删除会误删。
- **M2. `parseInsertValues` 无法处理转义引号**（`database.ts` 约 L210-240）：遇到 SQL 转义写法 `''` 或值内引号会提前结束字符串，导致字段值错位写入。与 H2 的 `feeding.vue` 转义方案在 H5 端冲突。
- **M3. `parseValue` 过度类型推断**（`database.ts` `parseValue`）：纯数字字符串（电话号、以 0 开头的批次号）被强转 Number 丢前导 0；`'true'/'false'` 被转布尔。与 APP 端按 TEXT 存原值不一致。
- **M4. import.ts SQL 注入面最大**（`import.ts` L84/L100）：`insertRecord`/`checkRecordExists` 拼接外部 JSON 文件的不可信数据，注入风险最高；且去重是 N 次单独 SELECT+INSERT（全表扫描×N），大数据量性能极差。
- **M5. import 漏导入 babyInfo**（`import.ts` L60-68）：tables 列表无 babyInfo，而 export 导出了它 → 导出能导出、导入丢失，往返不对称。
- **M6. export 强依赖 H5 不支持的 ORDER BY**（`export.ts` L8-15）：H5 导出顺序为插入顺序，与 APP 降序不一致。

### 页面层

- **M7. 疫苗页重复初始化竞态**（`vaccine/index.vue` L191-200、L341）：空查询触发初始化、catch 里再触发、onShow 又调一次，多路径可能重复插入整套疫苗；`unique_id` 用 `Date.now()` 在毫秒内循环生成会冲突。建议 `INSERT OR IGNORE` + 真正唯一 id + 并发锁。
- **M8. 疫苗排期依赖生日但生日可能为空**（`vaccine/index.vue` L228-231）：初始化时若 babyBirthday 为空则用 `Date.now()` 当生日，导致所有 scheduled_date 基于"今天"计算，月龄/排期全错。
- **M9. 成长曲线数据点与 x 轴标签错位**（`growth/index.vue` L255-270）：data 用 `.filter(v => v > 0)` 过滤空值，categories 却用全部记录，长度不匹配导致曲线点与标签错位。应同源过滤、成对剔除。
- **M10. 喂养/历史列表 LIMIT 50 截断**（`feeding/index.vue` L165-216）：feeds 和 foods 各取 50 条合并，超出部分丢失，"全部"列表实则缺数据。建议统一时间游标分页。
- **M11. onShow 重复全量初始化**（`index/index.vue` L268-281 等）：每次页面显示都 `db.open()` + `initTables()` + 全量查询，无 loading、无防抖。`open`/`initTables` 应只在 `onLaunch` 执行一次。
- **M12. typeMeta / 图标标签三处重复维护**（`index/index.vue` L66-75、`feeding/index.vue` L122-135、`QuickRecord.vue` L19-28）：母乳/配方奶/辅食的 label、icon 多处复制，易不一致。建议抽到 `utils/constants.ts` 共享。

### 工程配置

- **M13. record 6 个记录页结构高度重复**：模板（form-section/form-item/form-actions）、样式（每页约 80-100 行重复 CSS）、逻辑（onTimeChange/handleCancel/handleSave 骨架、uniqueId 生成）几乎逐字复制。建议抽 `RecordFormShell` 组件 + `useRecordSave(table, buildRow)` composable，顺带集中治理 SQL 转义。
- **M14. 提醒功能仅 APP 端有效**（`reminder.ts`）：全部能力在 `#ifdef APP-PLUS` 内，H5/小程序静默无效且无降级提示；`setFeedingReminder` 实为单次延时通知而非周期循环提醒。

## 四、🟡 低危问题与优化点

### 代码质量

- **L1. 首页死代码 / 未声明 ref**（`index/index.vue`）：经核实，`index.vue` 中**无 `vaccineProgress`/`photoCount` 的 ref 声明**，但存在对它们赋值的 `loadVaccineProgress`/`loadPhotoCount` 函数（定义后从未被调用）。属定时炸弹，应删除死代码或补全声明并接入。
- **L2. 调试日志残留**：`database.ts`、`vaccine/index.vue`（L165-260 多处）等大量 `console.log` 未清理（`vite.config.ts` 已配 `drop_console:true`，生产会移除，但开发期噪音大）。
- **L3. growthCurve 死代码**：`getNearestMonth` 定义后从未被调用。
- **L4. growthCurve 百分位为线性插值非真实 LMS 模型**：`estimatePercentile` 注释称"正态分布"实为线性插值，极端值误差大，UI 应标注"估算"。
- **L5. `addColumnIfNotExists` try/catch 吞掉所有错误**（`database.ts`）：靠捕获异常判断列是否存在，会掩盖真实建表/权限错误。
- **L6. `isOpen` 字段形同虚设**（`database.ts`）：定义后几乎未用于任何守卫。

### 工具/设备

- **L7. getDeviceId 用 Math.random + 已废弃的 substr**（`device.ts` L9）：非加密随机有极小碰撞概率，`substr` 已废弃，建议 `slice`。
- **L8. formatTime 用字符串 replace 非全局正则**（`device.ts` L35-41）：含重复占位符时只替换首个，属脆弱设计。
- **L9. vaccineData 用 magic number**：狂犬病疫苗 `ageMonths: -1` 作哨兵值；`getVaccineFullName` 直接拼 name+dose 对非剂次描述语义怪异。

### 页面体验

- **L10. 普遍缺 loading 态与严谨空态**：成长页、喂养页、首页切换/查询时列表无反馈；成长页 `hasData` 仅看记录条数，无有效数据点时显示空图而非空态。
- **L11. 母乳时长显示精度**（`feeding/index.vue` L177-181）：`Math.floor(left/60)` 不足 1 分钟显示"0 分钟"。
- **L12. settings 用 onMounted 而非 onShow**：从其他页改数据返回设置页不刷新，与其他页生命周期不一致；保存无输入校验。
- **L13. QuickRecord 细节**：`ref` 包裹纯静态常量、`:key="index"`、emit 无类型签名。

### 工程配置

- **L14. 依赖版本宽松**（`package.json`）：uni 全家桶用 `^3.0.0` 不锁版本易引入不兼容；`typescript ^4.9` 偏旧；`qiun-data-charts` 引入但部分页面未用。
- **L15. manifest 权限过度声明**（`manifest.json`）：声明 `CAMERA`/`INTERNET`/`WRITE_EXTERNAL_STORAGE`，与"本地 SQLite 记录"功能不匹配，存在隐私合规风险；`appid` 为空、`mp-weixin.urlCheck:false`。
- **L16. 疑似新旧两套页面路径并存**（`pages.json`）：`pages/feeding/index` 与 `pages/record/feeding` 并存，需确认是否有冗余页面。
- **L17. TS 严格度收益被 any 抵消**：`tsconfig.json` 已开 `strict`，但记录页大量 `(e: any)`、`options: any` 削弱类型收益；可补 `noUnusedLocals` 等。

## 五、修复优先级建议

按"根因优先、影响面排序"建议分四批推进：

### 第一批：根因级修复（解决数据正确性与崩溃）
1. **H1 补齐 6 张记录表的建表语句** —— 否则 APP 真机端记录功能完全不可用，这是最高优先级。
2. **H2 数据层参数化 / 统一转义** —— 从根上消除 SQL 注入与单引号写库失败，记录页随之改造。
3. **H3 H5 解析器补齐**（ORDER BY / SUM / 范围操作符）—— 消除跨端统计与排序的系统性错误。
4. **H4 修复 H5 自增 id 生成**。

### 第二批：功能正确性
5. **H5 记录页时间入库**（diaper/food/supplement/growth）。
6. **H6 settings 保存 gender** + **H8 growth 数值校验**。
7. **H7 clearAllData 补全表**。
8. **M7/M8 疫苗初始化竞态 + 生日依赖**、**M9 成长曲线点错位**。

### 第三批：可维护性重构
9. **M13 抽 RecordFormShell + useRecordSave**（顺带集中治理转义）。
10. **M12 抽公共 typeMeta 常量**。
11. **L1/L3 清理死代码**、**M1-M6 数据层健壮性修复**。

### 第四批：体验与工程打磨
12. **L10 补 loading/空态**、**M11 onShow 重复初始化优化**。
13. **L14-L17 工程配置**（锁版本、收敛权限、清理冗余页面、增强类型）。
